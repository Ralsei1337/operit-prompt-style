# 输出风格助手

## 它解决什么问题

同一个助手，不同轮次的回复结构常常漂移：有时先铺三段背景再给结论，有时一句"我理解你的需求"开场，有时缺个参数就停下来反问，有时工具报错就在原地重试五次。

这不是能力问题，是**输出形态没有约束**。本插件在系统提示词组装时追加一段输出规范，把回复结构钉住。

## 三条能力

### 1. 输出规范注入

在 `after_compose_system_prompt` 阶段追加七条格式约定：

| 约定 | 作用 |
| --- | --- |
| 结论先行 | 第一段给结果本身，说明放后面 |
| 不写开场套话 | 不复述问题，不写"我理解你的需求" |
| 篇幅贴合复杂度 | 一句话能答完的不写三段 |
| 缺信息用占位符 | 标注 `[TARGET]` 继续推进，不停下等 |
| 工具失败换实现 | 换参数/命令/接口，不原地重试 |
| 长任务给阶段结论 | 让读者中途能判断方向 |
| 区分已确认与未验证 | 推测必须标注 |

### 2. 三档风格

| 档位 | 差异 |
| --- | --- |
| 精简 `concise` | 只有中文条目，省掉英文对照，上下文占用最小 |
| 平衡 `balanced` | 中英对照，推荐默认 |
| 详尽 `detailed` | 追加取舍理由、边界条件、验证方式、被放弃的方案 |

### 3. 工具清单收敛

`hidePatterns`（支持结尾 `*`）在 `filter_tool_prompt_items` 与 `filter_tool_call_tools` 两个阶段剔除工具。工具太多时模型会瞎调，收敛清单能明显降低无效调用。

配合调用审计（`tool-audit.jsonl`）可以看出哪些工具从没被用过，直接隐藏。

## 设计原则

**只改输出格式。** 规范正文里每一条都是可观察的输出约定，不涉及人格、语气、内容取向。正文末尾明确写着"与角色设定、语气、内容取向无关"，单测里有一条用例守着这个边界（禁词扫描）。

**幂等。** 注入段带标记 `<!-- prompt-style-assistant:profile -->`，重复 compose 直接返回 `null`，不会越叠越长。

**可预览。** `previewOnly` 模式下只记录将要注入的字符数，不改写提示词。装完第一件事就该开这个看看效果。

**可回滚。** 每次改配置先留快照，`/style revert` 一键回退。

**失败不崩。** 文件读取失败、配置损坏、钩子异常全部回落默认值并返回 `null`，不阻断用户对话。单测里有模拟文件系统故障的用例。

## 与角色卡的关系

不冲突。角色卡管"是谁、怎么说话"，本插件管"回复怎么组织"。两者作用在不同层：

- 角色卡：身份、性格、语音模式、话题策略
- 本插件：段落顺序、开场方式、长度、信息缺口处理

如果角色卡里有"必须始终先征询用户同意"这类**流程性**要求，与本插件的"缺信息用占位符继续"会有摩擦。处理方式是改角色卡那一条，而不是关掉本插件。

## 已知边界

- 只影响 `after_compose_system_prompt` 阶段。如果某条链路绕过了系统提示词组装（如独立的小工具调用），规范不生效。
- 不改工具的实际权限。隐藏工具只是让它不出现在模型可见清单里，不等于禁用。
- 审计记录写入本地配置目录，不上传、不联网。
